
## Group 5 — Signature Verification

### TC-5.1 · Valid Stripe signature is accepted

**Requires:** Sink with `webhookSecret: "whsec_test123"`. Use Stripe CLI to fire a test event.

**Steps:**

```bash
stripe trigger payment_intent.succeeded \
  --webhook-endpoint http://localhost:3000/ingest/:sinkId
```

**Success:** `200 { "received": true }`. Event status is `pending` or `delivered` — not `rejected`.

---

### TC-5.2 · Tampered Stripe payload is rejected

**Steps:**

1. Compute a valid Stripe signature manually for payload A
2. Send payload B with payload A's signature

**Success:** `400 { "error": "Invalid signature" }`. Event is not stored.

---

### TC-5.3 · Missing Stripe signature header is rejected

**Steps:**

1. POST to `/ingest/:sinkId` with no `stripe-signature` header (Stripe provider)

**Success:** `400 { "error": "Missing signature" }`

---

### TC-5.4 · Valid GitHub signature is accepted

**Requires:** Sink with `provider: "github"` and a `webhookSecret`

**Steps:**

1. Compute HMAC-SHA256 of payload with the secret
2. POST with header `x-hub-signature-256: sha256=<hmac>`

**Success:** `200 { "received": true }`

---

### TC-5.5 · Sink with no webhookSecret — signature check is skipped

**Requires:** Sink created without `webhookSecret`

**Steps:**

1. POST to `/ingest/:sinkId` with arbitrary body, no signature header

**Success:** `200 { "received": true }`. Event stored with `status: "pending"`.
